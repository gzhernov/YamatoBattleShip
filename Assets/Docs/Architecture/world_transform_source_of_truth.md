# Архитектурная фиксация: `WorldTransform` как источник истины

## Статус

Принято для реализации плана `plan_worldagent_floating_origin_stages_1_3`, этап 1, пункт 1.

## Решение

Источником истины для пространственного состояния любой мировой сущности является `WorldTransform`, а не Unity `Transform`.

Это означает:

- игровая логика читает и изменяет позицию, поворот и масштаб через `WorldTransform`
- Unity `Transform` используется только как локальное визуальное представление в текущей системе координат сцены
- любые пересчёты после `Floating Origin rebase` должны менять локальное Unity-представление, но не истинное мировое состояние сущности

## Почему это решение принято

Unity `Transform` хранит координаты в `float` и привязан к текущему локальному нулю сцены. Для морской карты большого размера этого недостаточно: при больших дистанциях накапливается ошибка, а `rebase` меняет локальные координаты объектов.

Если считать Unity `Transform` источником истины, то:

- симуляция начнёт зависеть от локального сдвига сцены
- точность движения и боевой логики будет ухудшаться по мере удаления от локального нуля
- `Floating Origin` станет затрагивать не только визуализацию, но и игровое состояние

`WorldTransform` отделяет истинное мировое состояние от локального Unity-представления и делает `rebase` безопасной операцией для симуляции.

## Инварианты

Следующие правила считаются обязательными:

1. У каждой мировой сущности есть собственный `WorldTransform`.
2. `WorldTransform` хранит истинное пространственное состояние сущности в мировых координатах.
3. Unity `Transform` не используется как постоянное хранилище мировой позиции.
4. После любого `rebase` значение `WorldTransform` остаётся неизменным.
5. Локальная позиция visual-объекта вычисляется из пары `WorldTransform + WorldOrigin`.

## Последствия для системы

### `WorldAgent`

- владеет или содержит `WorldTransform`
- является точкой входа для мировой сущности в сцене
- может переживать создание и удаление `visualObject` без потери мирового состояния

### `WorldManager`

- хранит текущий `WorldOrigin`
- предоставляет преобразование из мировых координат в локальные Unity-координаты
- инициирует `rebase`, не переписывая `WorldTransform` зарегистрированных сущностей

### Визуальное представление

- `visualObject.transform.position` является производным значением
- `visualObject.transform.rotation` и `visualObject.transform.localScale` синхронизируются из `WorldTransform`
- восстановление визуала всегда должно быть возможно только по данным `WorldTransform` и текущего `WorldOrigin`

## Базовая формула

```text
LocalUnityTransform = WorldTransform - WorldOrigin
```

Для позиции это означает:

```text
localPosition = worldPosition - worldOrigin
```

## Практическое правило для разработки

Если системе нужно ответить на вопрос "где объект находится на самом деле?", она должна обращаться к `WorldTransform`.

Если системе нужно ответить на вопрос "где объект сейчас нужно показать в Unity-сцене?", она должна использовать локальный `Transform`, пересчитанный из `WorldTransform` относительно текущего `WorldOrigin`.
